# 전략 로직 상세 (Strategy Logic)

이 문서는 현재 시스템의 의사결정 로직(계좌별 순위 계산)을 설명합니다.

## 1. 공통 실행 원칙

* 순위 화면은 계좌에 등록된 전체 종목 유니버스를 직접 사용합니다.
* 계산 기준은 당일 종가 기준입니다.
* 최신 거래일 판단의 기준 날짜는 모든 시장 공통으로 한국 날짜를 사용합니다.
* 필수 설정이 누락되면 fallback 없이 명시적 에러로 중단됩니다.
* 순위 비교에 사용하는 `이전순위`는 현재 화면에 적용된 보유보너스(%)를 포함한 동일 조건으로 이전 거래일을 다시 계산해 얻습니다.

## 2. 계좌 순위 계산 로직

종목풀(`pools.json`)은 등록된 전체 종목을 유니버스로 사용하고, `MA_TYPE`, `MA_MONTHS` 기준으로 각 종목의 점수를 계산합니다.
버킷은 분류/표시용 참고 정보로만 사용합니다.

### 핵심 파라미터

* `MA_TYPE`: 이동평균 타입
* `MA_MONTHS`: 이동평균 기간(개월)
* `TOP_N_HOLD`: 보유 상위 종목 수
* `HOLDING_BONUS_SCORE`: 보유보너스(%) — 보유 종목 점수 비중.
* `TREND_WEIGHT_RATIO`: 추세 가중치(%) — 보유 제외 나머지 비중 중 추세 몫. 추세 = `(100−보유%)×r/100`, 샤프 = `(100−보유%)×(100−r)/100` (풀별 설정).
* 위 편집값(`TOP_N_HOLD`/`HOLDING_BONUS_SCORE`/`TREND_WEIGHT_RATIO`/`MA_TYPE`/`MA_MONTHS`/`RSI_LIMIT`)은 DB `pool_settings` 가 단일 소스이며 종목풀 순위·설정 화면에서 편집한다.

### 동작 요약

점수는 **세 요소(추세·샤프·보유)를 합이 100%인 비중으로 가중 합산**한다. 보유보너스(%)를 `보유%`, 추세 가중치(%)를 `r`이라 하면 추세 비중 = `(100−보유%)×r/100`, 샤프 비중 = `(100−보유%)×(100−r)/100` (예: 보유 10%·r 70 → 추세 63%·샤프 27%).

1. 종목풀 전체 종목에 대해 `MA_TYPE`, `MA_MONTHS` 기준 단일 추세 값을 계산한다
2. 추세 값을 `0` 기준으로 상승/하락 구간으로 나눈다
3. 각 구간 안에서만 상대 순위(백분위)를 계산하고 부호를 유지한다 → **추세 원점수**(−100 ~ +100)
4. **샤프 원점수(−100 ~ +100)**: 3개월 롤링 샤프지수를 계산한 뒤 추세와 동일하게 **양/음 구간별 signed-백분위**(양수는 양수끼리 0~100, 음수는 음수끼리 −100~0)로 환산한다 — 위험조정 수익이 높을수록 높다.
5. **보유 원점수**: 실보유 종목은 `100`, 아니면 `0` (히스테리시스로 회전율을 낮춘다).
6. **가중 합산**: `점수 = (w/100)×추세 + (w/100)×샤프 + 보유가점`. 여기서 `보유가점 = 보유 시 보유%`(= 보유 원점수 100 × 보유%/100). 세 요소 비중의 합은 항상 100%다.
   * 라이브(`utils/rankings.py`)와 백테스트(`backtest/engine.py`)가 **동일한 식**을 쓴다(공통 엔진 `core/strategy/scoring.py`의 `compute_secondary_metric_points`·`compute_sharpe_signed_percentile` 등). 화면에는 `추세`(±100)·`샤프`(±100) 컬럼으로 원점수를 표시한다(`보유` 컬럼은 숨김).
7. `MIN_TRADING_DAYS` 이상 데이터가 있는 종목만 점수 계산 대상이 된다
8. `점수` 내림차순으로 정렬한다
9. 데이터가 부족한 종목은 `점수` 계산 불가로 처리하고 맨 아래에 둔다
10. 실제 보유 종목은 화면에서 녹색 행으로 강조한다
11. `고정 종목`은 순위 번호 없이 현재 점수 위치만 참고용으로 표시한다 (보유가점 제외)

### 화면 표시 규칙

* 실제 보유 여부는 `summary_details` 기반 실보유 데이터로만 판단합니다.
* 결과 테이블은 `점수` 내림차순입니다.
* `고정 종목`은 `📌 고정`으로 표시합니다.
* `현재가` 뒤에 `점수`, `추세`, `샤프` 컬럼이 순서대로 위치합니다(`추세`·`샤프` 모두 ±100 원점수를 +/− 기호와 검은색으로 표시). `보유` 컬럼은 숨김 처리됩니다.

### 검증 규칙

* `MA_TYPE`, `MA_MONTHS`는 종목풀 설정에 있어야 함
* `점수` 계산 불가 종목은 맨 아래로 보내야 함
* 실제 보유 종목 강조는 순위 계산과 별도로 적용되어야 함

## 3. 탑픽 포트폴리오 (`/top-pick`)

탑픽은 등록된 ETF 후보군을 계좌와 분리된 가상 포트폴리오로 계산합니다. 비중 방식(`weight_mode`), 설정과 백테스트 설정(`backtest_settings`)은 MongoDB `top_pick_settings`의 계좌별 문서가 단일 소스입니다.

* 점수는 기존 모멘텀 점수 계산을 재사용해 `추세`와 `Sortino`를 설정 비중으로 합산합니다.
* `weight_mode=fixed`이면 최소·최대 비중과 시장 레짐을 적용하지 않고 저장된 종목별 고정 비중을 그대로 사용합니다.
* 목표 비중은 모든 종목에 최소 비중을 먼저 배정하고, 남는 비중은 점수 순위가 높은 종목에 더 많이 배정합니다.
* `추세(%) <= 0`인 종목은 방어 대상으로 보고 추가 비중 배정을 제한합니다.
* 현금 비중은 `방어 대상 종목 수 / 전체 종목 수 × 현금 최대 비중`으로 계산합니다.
* 방어 대상이 없는 경우 현금 비중은 0%이며, ETF에 100% 투자합니다.
* 성장 대상의 최대 비중과 현금 최대 비중으로도 100%를 채울 수 없을 때만 방어 대상 종목에도 덜 나쁜 순서로 추가 비중을 배정합니다.
* 목표금액과 목표수량은 설정에 저장된 적용 계좌의 실제 총자산과 현재가 기준으로 계산하며, 현재 보유수량과 비교해 변동수량을 산출합니다.
* 탑픽 설정 화면의 백테스트는 최초 금액(만원)을 원화 초기자본으로 환산한 뒤 같은 점수·현금 규칙을 과거 리밸런싱 시점마다 적용하고, 리밸런싱 사이에는 가격 변동으로 드리프트된 종목·현금별 평가금액 이력(`weight_history`)을 매주 금요일 기준으로 반환합니다.

## 4. 시장지수 추세 (`/market-trend`)

코스피·코스피200·S&P500·나스닥100 지수의 추세를 점수화하고 레짐(국면)을 보여줍니다.
관련 파라미터는 모두 `config.py` 가 단일 진실 소스이며, 프론트에는 API
응답(`/internal/market-trend/defaults`)으로 전달됩니다.

### 추세 점수 (−100 ~ +100)

1. 원본 추세% = `(종가 ÷ MA[MA_TYPE, MA_MONTHS] − 1) × 100` (MA선이면 0, 위면 +, 아래면 −)
2. 최근 12개월 추세% 분포에서 **상위 P 퍼센타일**(`MARKET_TREND_SCORE_ANCHOR_PERCENTILE`, 기본 95)을 +100,
   **하위 (100−P) 퍼센타일**을 −100 으로 두고 정규화 (MA선=0점 고정)
3. 상위 P% 이상은 +100 에 포화. 단발 최대/최소가 아닌 퍼센타일이라 이상치에 둔감하고 자기보정됨
4. **수익률이 아니라 MA 대비 위치의 정규화 점수**임

### 레짐 (상승 / 중립 / 하락) — 레벨 기반

**그날의 지수 위치만으로** 판정합니다 (기울기 없음). 방향 = 지수 vs 장기MA(화면 선택 MA),
모멘텀(강/약세) = 지수 vs 단기MA ± 버퍼:

* 강세 승격: 종가 > 단기MA×(1+버퍼) 가 `MARKET_TREND_REGIME_CONFIRM_DAYS`(기본 3) **연속**일 때만
  — 며칠짜리 반등(휩소)으로 상승 라벨이 붙는 것을 차단.
* 약세 전환: 종가 < 단기MA×(1−버퍼) → **즉시** (하락은 기민하게).
* 버퍼(`MARKET_TREND_REGIME_BUFFER_PCT`, 기본 0.5%) 안이면 직전 강/약세 상태 유지 (연속 카운트는 리셋).
* 단기MA 기간: `MARKET_TREND_REGIME_SHORT_MA_DAYS`(기본 20거래일), 타입은 화면 선택 MA 와 동일.
* 매핑: 장기MA 위+강세=상승, 위+약세=중립, 아래+강세=중립, 아래+약세=하락.
* 전환 예측 경계도 같은 규칙으로 역산합니다 — 경계가 가격 레벨이라 "이 가격 아래로 내려가면 중립"
  형태로 자연스럽고, 상승 승격은 연속일 요건 때문에 내일 하루로 불가능하면 경계가 None 입니다.
* 레짐 라벨은 추세 점수 계산과 독립입니다 (라벨 안정화 목적).

## (부가) 레버리지 전략 — `leverage/`

순위/모멘텀 로직과 별개로, 폐기된 `leverage-switching` 앱에서 이전된 레버리지 스위칭 전략을 `leverage/` 패키지로 운용합니다. 설정·튜닝 탐색공간·상태는 MongoDB(`leverage_config`/`leverage_state`)가 단일 소스입니다.

* **switch (2-Tier 히스테리시스 스위칭)**: 시그널 지수(KODEX 코스피)의 고점 대비 하락률이 매도 컷보다 깊어지면 방어 자산으로, 매수 컷보다 회복되면 공격 자산(레버리지 ETF)으로 전환. 매수/매도 컷을 분리해 횡보장 휩소를 줄입니다.
* **공격 자산 동적 선택**: 공격 자산은 고정이 아니라, 방어→공격 진입 시점마다 공격 후보군 중 **ALMA 6개월 이격도(종가/ALMA−1) 1위** 종목을 선택합니다. 진입 후에는 매도 신호까지 같은 자산을 유지하며, 백테스트·튜닝·라이브 추천이 모두 동일 규칙을 씁니다. 최근 상장 후보는 상장 이후 구간에서만 선택 대상이 됩니다.
* **실행 원칙**: 신호는 **마지막으로 닫힌 거래일 종가**로 확정(장중에는 오늘 미완성 봉 제외), 익일 시초가 실행 가정. 장중 추천 화면/Slack 에서는 현재가·드로다운·회복필요 등 표시값만 실시간으로 갱신하고 포지션은 바꾸지 않습니다.
* **튜닝**: 전수 탐색으로 매수/매도 컷오프·방어 후보를 최적화해 DB(`leverage_config`) 설정 갱신 (공격 자산은 튜닝 대상이 아니라 진입 시 동적 선택).
