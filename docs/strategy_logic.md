# 전략 로직 상세 (Strategy Logic)

이 문서는 현재 시스템의 의사결정 로직(계좌별 순위 계산)을 설명합니다.

## 1. 공통 실행 원칙

* 순위 화면은 계좌에 등록된 전체 종목 유니버스를 직접 사용합니다.
* 계산 기준은 당일 종가 기준입니다.
* 최신 거래일 판단의 기준 날짜는 모든 시장 공통으로 한국 날짜를 사용합니다.
* 필수 설정이 누락되면 fallback 없이 명시적 에러로 중단됩니다.
* 순위 비교에 사용하는 `이전순위`는 현재 화면에 적용된 추세 조건으로 이전 거래일을 다시 계산해 얻습니다.

## 2. 계좌 순위 계산 로직

종목풀(DB `pool_settings`)은 등록된 전체 종목을 유니버스로 사용하고, SMA 고정 메인 이평선(`MAIN_MA_DAYS`) 기준으로 각 종목의 추세(%)를 계산합니다.
버킷은 분류/표시용 참고 정보로만 사용합니다.

### 핵심 파라미터

* `SHORT_MA_DAYS`: 정배열/역배열 판단용 단기 이동평균 기간(거래일)
* `MAIN_MA_DAYS`: 추세(%) 계산용 메인 이동평균 기간(거래일)
* `TOP_N_HOLD`: 보유 상위 종목 수
* 종목풀 구조와 편집값(`TOP_N_HOLD`/`SHORT_MA_DAYS`/`MAIN_MA_DAYS`)은 DB `pool_settings` 가 단일 소스이며 종목풀 설정 화면에서 추가·수정·삭제한다.

### 동작 요약

선정 기준은 **추세(%) 단독**이다. 보유 여부는 행 강조와 보유 유지 판단에는 사용할 수 있지만, 종목 선정에는 가점을 주지 않는다.

1. 종목풀 전체 종목에 대해 SMA 고정 메인 이평선(`MAIN_MA_DAYS`) 기준 단일 추세 값을 계산한다
2. 추세 값은 `종가 ÷ MA − 1` 기준 이격률(%)이다
3. 단기 이평선(`SHORT_MA_DAYS`)이 메인 이평선 위에 있으면 정배열, 아래에 있으면 역배열로 표시한다
7. `MIN_TRADING_DAYS` 이상 데이터가 있는 종목만 추세(%) 계산 대상이 된다
8. `추세(%)` 내림차순으로 정렬한다
9. 데이터가 부족한 종목은 `추세(%)` 계산 불가로 처리하고 맨 아래에 둔다
10. 실제 보유 종목은 화면에서 녹색 행으로 강조한다
11. `고정 종목`은 순위 번호 없이 현재 추세 위치만 참고용으로 표시한다

### 화면 표시 규칙

* 실제 보유 여부는 `summary_details` 기반 실보유 데이터로만 판단합니다.
* 결과 테이블은 `추세(%)` 내림차순입니다.
* `고정 종목`은 `📌 고정`으로 표시합니다.
* `현재가` 뒤에 `추세(%)` 컬럼이 위치합니다. `보유` 컬럼은 숨김 처리됩니다.

### 검증 규칙

* `SHORT_MA_DAYS`와 `MAIN_MA_DAYS`는 종목풀 설정에 있어야 함
* `추세(%)` 계산 불가 종목은 맨 아래로 보내야 함
* 실제 보유 종목 강조는 순위 계산과 별도로 적용되어야 함

## 3. 탑픽 포트폴리오 (`/top-pick`)

탑픽은 등록된 ETF 후보군을 계좌별 목표 포트폴리오로 계산합니다. 설정과 백테스트 설정(`backtest_settings`)은 MongoDB `top_pick_settings`의 계좌별 문서가 단일 소스입니다.

* 선정 기준은 기존 모멘텀 추세(%) 계산을 재사용하며, Sortino는 종목 선정에 사용하지 않습니다.
* 목표 비중은 편입 종목 수 `N`으로 나눈 동일 슬롯(`1/N`)을 기준으로 합니다.
* 각 종목이 설정된 추세선 위에 있으면 해당 슬롯만큼 투자하고, 추세선 아래에 있으면 해당 슬롯을 현금으로 둡니다.
* 시장 레짐, 최소·최대 비중, 상승·중립·하락 현금 비중, `weight_mode`는 탑픽 비중 계산에 사용하지 않습니다.
* 목표금액과 목표수량은 설정에 저장된 적용 계좌의 실제 총자산과 현재가 기준으로 계산하며, 현재 보유수량과 비교해 변동수량을 산출합니다.
* 탑픽 설정 화면의 비중 계산과 백테스트는 해당 계좌에 연결된 단일 종목풀의 `MAIN_MA_DAYS`를 추세선 기준으로 사용합니다. 백테스트는 최초 금액(만원)을 원화 초기자본으로 환산한 뒤 같은 슬롯·추세선 규칙을 과거 리밸런싱 시점마다 적용하고, 리밸런싱 사이에는 가격 변동으로 드리프트된 종목·현금별 평가금액 이력(`weight_history`)을 매주 금요일 기준으로 반환합니다.

## 4. 시장지수 추세 (`/market-trend`)

코스피·코스피200·S&P500·나스닥100 지수의 추세를 점수화하고 레짐(국면)을 보여줍니다.
관련 파라미터는 모두 `config.py` 가 단일 진실 소스이며, 프론트에는 API
응답(`/internal/market-trend/defaults`)으로 전달됩니다.

### 추세 점수 (−100 ~ +100)

1. 원본 추세% = `(종가 ÷ SMA20 − 1) × 100` (MA선이면 0, 위면 +, 아래면 −)
2. 최근 12개월 추세% 분포에서 **상위 P 퍼센타일**(`MARKET_TREND_SCORE_ANCHOR_PERCENTILE`)을 +100,
   **하위 (100−P) 퍼센타일**을 −100 으로 두고 정규화 (MA선=0점 고정)
3. 상위 P% 이상은 +100 에 포화. 단발 최대/최소가 아닌 퍼센타일이라 이상치에 둔감하고 자기보정됨
4. **수익률이 아니라 MA 대비 위치의 정규화 점수**임

### 레짐 (상승 / 중립 / 하락) — MA20/60 교차 기반

레짐 판정 정본은 `MA20/60 교차 + 지수별 확인일수`입니다.

* MA20 < MA60 → 하락.
* MA20 ≥ MA60 이면서 종가 > MA20 → 상승.
* MA20 ≥ MA60 이면서 종가 < MA60 → 하락.
* 그 외, 즉 MA20 ≥ MA60 이면서 종가가 MA20~MA60 사이 → 중립.
* 새 레짐은 `MARKET_TREND_REGIME_CONFIRM_DAYS[yf_ticker]`의 N값을 적용해 `(N+1)`거래일 연속 확인될 때 확정됩니다. N=0이면 즉시 전환입니다.
* `/market-trend` 차트의 SuperTrend 선과 화살표는 보조 시각화로 유지하지만, 레짐·탑픽 현금비중·레짐 백테스트의 판단 기준은 아닙니다.
* 전환 조건은 MA20/MA60 가격선과 남은 확인일수로 표시합니다.

## (부가) 레버리지 전략 — `leverage/`

순위/모멘텀 로직과 별개로, 폐기된 `leverage-switching` 앱에서 이전된 레버리지 스위칭 전략을 `leverage/` 패키지로 운용합니다. 설정·튜닝 탐색공간·상태는 MongoDB(`leverage_config`/`leverage_state`)가 단일 소스입니다.

* **switch (2-Tier 히스테리시스 스위칭)**: 시그널 지수(KODEX 코스피)의 고점 대비 하락률이 매도 컷보다 깊어지면 방어 자산으로, 매수 컷보다 회복되면 공격 자산(레버리지 ETF)으로 전환. 매수/매도 컷을 분리해 횡보장 휩소를 줄입니다.
* **공격 자산 동적 선택**: 공격 자산은 고정이 아니라, 방어→공격 진입 시점마다 공격 후보군 중 **SMA 20일 이격도(종가/SMA−1) 1위** 종목을 선택합니다. 진입 후에는 매도 신호까지 같은 자산을 유지하며, 백테스트·튜닝·라이브 추천이 모두 동일 규칙을 씁니다. 최근 상장 후보는 상장 이후 구간에서만 선택 대상이 됩니다.
* **실행 원칙**: 신호는 **마지막으로 닫힌 거래일 종가**로 확정(장중에는 오늘 미완성 봉 제외), 익일 시초가 실행 가정. 장중 추천 화면/Slack 에서는 현재가·드로다운·회복필요 등 표시값만 실시간으로 갱신하고 포지션은 바꾸지 않습니다.
* **튜닝**: 전수 탐색으로 매수/매도 컷오프·방어 후보를 최적화해 DB(`leverage_config`) 설정 갱신 (공격 자산은 튜닝 대상이 아니라 진입 시 동적 선택).
