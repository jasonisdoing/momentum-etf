# 테스트 작성 규칙

1. 테스트는 틀리면 돈이나 판단이 어긋나는 경로에만 둔다.
   - 화면의 운용 결과 = 백테스트 엔진 결과 (항상 유지)
   - 주문으로 이어지는 경로: 신호 선점·중복 방지·회수·잠금, 합성 주문
2. 새 파일을 만들지 않고 영역별 기존 파일에 추가한다.
   - 화면=백테스트·목표 비중 → `test_screen_matches_backtest.py`
   - 사고팔기 신호·회수·잠금·자동 주문 → `test_manual_trade_signals.py`
   - 합성 주문 → `test_strategy_mix_orders.py`
3. 전략 내부 현금 비중은 화면=백테스트 목표 비중 비교에 포함한다. 현금·예산·정수 배분만 따로 떼어 테스트하지 않는다.
4. 문구·입력 검증·캐시 호출·내부 함수 구현·수집 처리는 테스트하지 않는다. 확인이 필요하면 실데이터로 호출해 결과만 보고한다.
5. 코드 변경으로 기존 테스트가 깨지면 코드 의도에 맞게 테스트를 고친다. 지우지 않는다.
